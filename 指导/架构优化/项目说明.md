# EduAgent —— 教育领域移动端 AI Agent

面向 K12 至大学阶段的教育 AI Agent 移动应用（智能学习助手）。Mono-repo，包含 Flutter 移动端、FastAPI 微服务后端与完整基础设施配置。

## 技术栈

| 层级 | 技术 |
|------|------|
| 移动端 | Flutter 3.x + Riverpod + Hive/SQLite + Dio |
| BFF / 推理网关 / Agent 编排 / 多模态 / API 代理 / 文档生成 | FastAPI (Python 3.11+) + Celery |
| 自有模型推理 | vLLM (Docker, OpenAI 兼容接口) |
| 数据库 | PostgreSQL 15 + pgvector |
| 缓存/队列 | Redis 7 |
| 对象存储 | MinIO（预签名 URL） |
| 容器化 | Docker Compose（网络隔离） |
| 反向代理 | Nginx |

## 目录结构

```
├── mobile/                 # Flutter 移动端（iOS/Android 一套代码）
├── backend/
│   ├── shared/             # 公共库：配置/DB/Redis/加密/JWT/模型
│   ├── bff/                # BFF + API 网关：鉴权、校验、限流、路由转发
│   ├── gateway/            # 推理网关：双轨路由（自有 vLLM / 用户 API）、SSE、降级
│   ├── agent/              # Agent 编排：记忆、RAG、工具系统、内容生成引擎、Celery
│   ├── multimodal/         # ASR/OCR/TTS/文档解析/图片预处理
│   ├── proxy/              # 用户 API Key 代理（解密/转发/额度追踪）
│   └── docgen/             # 文档生成：python-pptx / python-docx / PDF
├── infra/
│   ├── postgres/init.sql   # 完整 DDL + pgvector + 索引 + RLS
│   └── nginx/nginx.conf    # 反向代理（SSL 终止/负载均衡）
├── docs/                   # 架构与 API 文档
│   ├── prompts/            # Master Prompt 设计文档
│   └── security/           # 安全审计报告（md 人读 + json 机读）
├── releases/               # 分发构建产物（APK/AAB，已 gitignore）
├── docker-compose.yml
└── .env.example
```

## 快速开始

```bash
cp .env.example .env   # 按需修改密钥与配置
docker compose up -d postgres redis minio
docker compose up -d   # 启动全部服务（vLLM 需要 GPU，可用 profile 控制）
```

移动端：

```bash
cd mobile
flutter pub get
flutter run
```

### 已有数据库卷的兼容修复

`init.sql` 只在数据库首次初始化时执行。已有卷若仍使用旧 DDL，当前 ORM 的学习计划、错题、记忆卡和教师内容等读写会因缺列失败。以下补丁仅对齐十张表现有 ORM 的 52 个缺列，保留旧列、数据、索引、RLS 和授权；首次新增列时回填，重复执行不覆盖已有值。先在隔离测试库验证，已有业务数据按现有备份流程保护。

```bash
docker compose exec -T postgres sh -c 'exec psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < infra/postgres/compat_orm_columns.sql
```

新建数据库已在 `init.sql` 中包含同一补丁。不要对已有库重跑整份初始化脚本，也不要删除卷来绕过兼容问题。补丁对齐结构，不负责修复历史失效签名或推断存储对象键。

## 移动端视觉设计规范

本项目移动端遵循 Anthropic 官方 `frontend-design` Skill 的设计原则（辨识度优先、避免模板化"AI 审美"），要点如下：

### 角色种子色（`mobile/lib/app/theme.dart`）

| 角色 | 色值 | 取意 |
|------|------|------|
| 学生 | `#2B50AA` | 墨水蓝（钢笔水） |
| 家长 | `#C2703D` | 暖杏色（宣纸 / 木质课桌） |
| 教师 | `#1F6F5C` | 松绿（黑板） |

刻意避开 Material 官方色板色号，全 App 配色由种子色经 `ColorScheme.fromSeed` 派生，深浅色模式自适应。

### 字体

- 标题 / 展示字体：**HarmonyOS Sans SC**（华为开源，Medium / Bold 两字重，文件与授权见 `mobile/assets/fonts/`）
- 正文：系统默认字体，保证阅读性与包体积

### 签名元素纪律

全 App 唯一的"渐变 + 光晕"元素是**语音录制按钮**（`voice_page.dart`）。其余品牌元素
（登录 Logo、聊天气泡、发送键、头像、步骤序号、AppBar 图标）统一为**纯描边、无色彩填充**，
让视觉重心聚焦于签名时刻。

## 测试

- 后端：各服务目录下 `pytest`
- 移动端：`cd mobile && flutter test`
- 网关降级单测：`backend/gateway/tests/test_failover.py`（模拟上游）
- 本地集成冒烟：`python3 backend/scripts/smoke_integration.py`（需已启动的七服务、PostgreSQL、Redis、MinIO 与一致的 `INTERNAL_SERVICE_TOKEN` 环境变量；dev/test 短信返回 dev_code）。脚本强制 internal 且关闭外部降级，验证未部署模型时的结构化错误，不调用付费外部模型。`--docker-network` 供同一 Compose 网络内执行时使用，不改变端口或网络隔离；完整通过仍需可用存储。
- 冒烟脚本回归：`python3 -m unittest discover -s backend/scripts -p 'test_*.py' -v`
- 数据库契约：`EDUAGENT_SCHEMA_TEST_DSN` 通过本机环境变量指定隔离测试库，再用安装了现有共享包及 SQLAlchemy/asyncpg 的解释器运行 `backend/scripts/verify_schema_contract.py`。脚本只接受回环地址，检查 18 个 ORM 读取及十张表写入，插入数据全部回滚；不创建或修改表。不要提供生产 DSN 或把凭证写入仓库。
