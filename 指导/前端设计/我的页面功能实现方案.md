## 2. Demo 状态与数据边界

- 昵称仅用于当前页面的模拟身份，不收集手机号、验证码或密码；刷新后回到访客。
- 历史为固定学习样例。打开历史会替换当前对话演示内容；当前新提问不会自动进入历史样例。正式产品需要按会话 ID 恢复，不能复制成新会话替代恢复。
- 收藏、学习偏好、减少动画开关及反馈草稿只在本次打开期间保留。退出模拟身份只切换外观，样例数据不是个人私有数据，也不代表跨账号数据隔离已实现。
- 阅读主题通过浏览器 localStorage 保存；不可用时仍可临时切换。system 模式监听系统变化，手动选择则脱离系统模式。
- 导出使用浏览器本地 Blob 文件，包含样例历史、收藏 ID、当前表单偏好和演示昵称，标记 `is_demo: true`。不包含账号凭证，不发起网络请求。
- 重置有确认与取消：恢复访客、默认两条收藏、默认学习阶段与讲解方式，清除反馈草稿和本地主题选择。
- 全部用户输入以纯文本进入 DOM；头像采用昵称首字，不加载远程图片。

## 4. 前端实现方案

### 账号与页面状态

账号使用 `guest / loading / authenticated / error` 状态；资料与认证令牌分开管理。访客仍可浏览明确标识的样例，登录成功后再加载本人数据。头像优先使用资料 URL，缺失或加载失败时回退为昵称首字；名称超长时限行，但完整名称可在资料页查看。

“我的”主入口保留账号区和分组列表，历史、收藏、设置、隐私和帮助各自进入子页，并可返回。恢复历史后切到聊天页，保留原 session ID 与翻页状态。页面需要覆盖加载、无结果、无数据、网络失败、会话已删除和认证过期。

### 数据与交互

- 历史列表采用游标分页和稳定排序，列表只加载摘要；打开后加载本人消息。搜索不在每次输入时全量拉取消息，采用短暂防抖、取消过期请求与分页搜索。
- 收藏以稳定资源 ID 标识；可乐观更新并在失败时回滚。连续点击需合并或禁用当前项写入，避免重复记录。
- 学习偏好分开维护草稿与已保存状态。明确保存成功后更新已保存值，失败保留草稿并提供重试；只把经过服务端校验的偏好用于讲解。
- 主题独立于登录；登出不应突然改变阅读外观。跨设备偏好冲突采用明确的版本或更新时间规则。
- 导出、删除或重置各自使用明确文案；本地重置不能称为账号删除。真实账号注销需要单独设计认证与数据保留规则。
- 表单保留标签、错误提示和焦点；触控目标至少 44px，320px 宽度不横向溢出。动画仍以短暂透明度和位移为主，此页不需要新增渲染引擎。

## 5. 后端与接口职责方案

以下为**待定的接口职责**，并非已经实现的新端点。优先对照已有路由，存在相同职责则扩展现有契约。

| 资源职责 | 请求/响应重点 | 约束与失败行为 |
| --- | --- | --- |
| 当前用户资料 | id、display_name、avatar_url、学习阶段；按实际持久化字段映射 | 用户 ID 从认证上下文取得；资料失败不误显示成已退出 |
| 本人会话列表与详情 | cursor、limit、可选查询；session_id、title、subject、updated_at；消息分页 | 详情与继续发送均校验归属；记录失效给出统一缺失状态 |
| 本人收藏 | source_type、source_id、created_at；幂等添加与移除 | 唯一约束防重复；写入前验证来源可见性，删除来源时定义降级策略 |
| 用户偏好 | theme、grade_level、explanation_style、reduce_motion、版本 | 枚举与长度校验；禁止任意偏好字符串直接覆盖系统提示词 |
| 反馈 | category、message、可选客户端版本；submission_id | 长度限制、限速、防重复；成功响应后才能展示真实提交成功 |
| 本人数据导出 | export_job_id、status、expires_at；短时下载位置 | 按本人范围打包，排除凭证与内部字段；鉴权、过期、失败重试均可见 |

真实历史、收藏、偏好和导出不能信任客户端传入的 user_id。登出/过期后停止旧用户请求，避免晚到响应写回新用户界面。游客升级为正式账号时，沿用现有用户升级流程，先定义数据归属和重复收藏合并规则，再实施迁移。

## 6. 数据库设计候选

这些是实现候选，**本轮没有创建表、修改字段、添加索引或执行迁移**。需与当前 ORM、DDL、BFF 资料结构逐项对齐后确定。

- 账号资料：复用 users；核查昵称、头像当前是否有一致的持久化来源，再决定补列，避免仅客户端有字段却无法重启恢复。
- 历史：复用 chat_sessions 与 messages，按 user_id 和 updated_at/稳定 ID 排序；评估现有索引后补充必要组合索引，不复制一份 history 表。
- 收藏：候选 `user_bookmarks`，包含 id、user_id、source_type、source_id、created_at；对 `(user_id, source_type, source_id)` 建唯一约束；根据资源类型设计外键或应用层归属验证。
- 偏好：候选一对一 `user_preferences` 或既有资料字段扩展；保存受控枚举和版本。已有 grade_level 优先复用，避免两个来源相互覆盖。
- 反馈/导出任务：按运营需求决定持久化；需要 user_id、状态、时间、过期/失败元数据。避免把凭证、原始异常或整个聊天记录默认写入反馈。
- 涉及本人数据的查询沿用项目隔离策略；补迁移时验证本人、跨用户、游客和空身份的可见性，并准备回滚与旧数据兼容方案。

## 7. 实施顺序与完成标准

| 顺序 | 交付物 | 验收条件 |
| --- | --- | --- |
| 1 | 资料与认证状态接入 | 真实登录/注册/退出、过期恢复正确；昵称头像可恢复；访客样例与本人数据不混用 |
| 2 | 历史与收藏接入 | 分页/搜索/继续会话/收藏幂等与失败回滚通过；跨用户读取被拒绝 |
| 3 | 主题与学习偏好接入 | 首屏无明显主题闪烁；系统外观跟随正确；偏好保存失败与跨设备冲突可恢复 |
| 4 | 帮助反馈、数据管理 | 反馈真实回执；导出只含本人数据、链接过期有效；本地重置与服务端删除含义明确 |
| 5 | 产品验收 | 手机/桌面、键盘/读屏、慢网/断网、长名称/空列表及低端设备滚动验收；另行决定上线 |

本轮已验证的只是设计稿：原有 34 项、输入区 14 项以及“我的”页 55 项浏览器检查。没有运行正式产品业务测试、调用真实模型、实现认证、申请系统权限或上线。
