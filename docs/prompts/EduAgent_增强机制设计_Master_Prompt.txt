# EduAgent —— Agent 增强机制设计 Master Prompt（编排层扩展包）

> **本文件定位**：本文档是《EduAgent 编排层设计 Master Prompt》（下称"编排层提示词"）的**扩展包**，
> 在编排层既有 11 项核心机制之上，新增 19 项增强机制（全部提炼自 Claude Code 架构并翻译为
> EduAgent 服务端形态）。两者必须配合使用：
> - 编排层提示词定义的基础红线（推理网关隔离、Celery 异步、护栏链、SSE 协议等）**全部继续有效**；
> - 本文件只定义新增机制；与编排层提示词表述冲突时，**基础安全红线以编排层为准，新增机制以本文件为准**。
>
> **总技术栈约束（不可越界）**：Python 3.11+ / FastAPI / Celery + Redis / PostgreSQL 15 + pgvector /
> MinIO / Flutter 3.x。所有机制落地于 `backend/agent/` 与 Flutter 端卡片协议，禁止引入其他运行时依赖。

## 二、分档一：交互协作机制

### 2.1 Plan Mode 两段式生成（P0）

**需求说明**：
1. **适用范围**（白名单）：制作 PPT、制作教案、生成试卷、学习计划、学情分析报告——长内容生成类 Skill。
   快问快答（拍照答疑、公式助手等）禁止进入 Plan 流程。
2. **流程状态机**：`drafting → awaiting_confirm → confirmed → generating → completed`，
   旁路状态 `cancelled / expired`。每次状态迁移推送 SSE 事件。
3. **大纲阶段**：Agent 生成 outline JSON（如试卷：题型分布/知识点覆盖/难度配比/逐题标题；
   PPT：每页标题+要点），以 `card_type: plan_outline` 卡片推送，进入 `awaiting_confirm`。
4. **确认协议**：确认请求携带 `confirm_token`（绑定 plan_id + user_id + 过期时间 30 分钟）。
   用户操作三选一：**确认**（→ confirmed，投递生成任务）/ **修改**（提交修改意见 → 回到 drafting，
   产生新 plan_version，旧版本保留）/ **取消**（→ cancelled）。超时未操作 → expired。
5. **同源约束**：生成任务（Celery）的入参必须包含**确认时的大纲快照**（outline_snapshot），
   生成内容以大纲为骨架展开，允许润色表述、禁止变更结构与范围。
6. **大纲阶段权限**：drafting/awaiting_confirm 期间 Agent 只允许调用只读工具
   （检索、计算、知识图谱查询），禁止任何写工具与文件生成。

**边界红线**：
| # | 红线 |
|---|------|
| 1 | 大纲未经 confirmed 状态，禁止投递任何 Celery 生成任务（代码上以前置状态校验强制） |
| 2 | 生成任务入参缺失 outline_snapshot 视为非法任务，Worker 必须拒收 |
| 3 | 用户修改大纲必须产生新 plan_version，禁止原地覆盖历史版本 |
| 4 | confirm_token 禁止跨用户、跨 plan 复用；过期 token 一律拒绝 |
| 5 | Plan Mode 不新增 SSE 协议外字段，大纲卡片走既有 `card` 事件 |

### 2.2 AskUserQuestion 结构化中途提问（P0）

**需求说明**：
1. **触发**：Agent 在 Loop 中调用内置工具 `ask_user_question`；Loop 挂起等待答复
   （挂起状态存 Redis，TTL 120s），答复到达后注入消息历史继续循环。
2. **问题协议**：每次最多 3 题；每题含 `question`、`options[]`（2–6 个，每项含
   `label ≤20字`、`description`、可选 `preview`）、`multi_select`（默认 false）。
3. **推荐项约定**：有推荐答案时，该选项必须放第一位且 label 末尾追加"（推荐）"。
4. **preview 预览**：选项为具体产物（大纲、模板风格、卷面样式）时必须携带 preview
   结构化内容，Flutter 渲染为**左选项列表 + 右预览**的并排卡片；简单偏好问题禁止滥用 preview。
5. **超时策略分级**：普通澄清超时 → 按推荐项默认值继续并在后续回答中明示；
   **敏感决策（付费、删除、公开发布、家长确认项）超时 → 一律按取消处理**。
6. **频次上限**：单次 run 内 ask 不超过 2 次；第 3 次需求必须合并进当次多问或放弃追问直接作答。

**边界红线**：
| # | 红线 |
|---|------|
| 1 | 能选项化的追问禁止退化为自由文本提问（评审以"选项覆盖率"抽查） |
| 2 | 敏感决策禁止使用"推荐项默认继续"策略，超时必须按取消处理 |
| 3 | ask 挂起期间禁止模型请求空转计费；恢复必须等用户答复或超时事件 |
| 4 | 每 run ask 次数 >2 视为缺陷；连续两个 turn 都 ask 视为缺陷 |

### 2.3 消息优先级队列与打断语义（P0)

**需求说明**：
1. **两级优先级**：`next`（控制类消息：停止、确认答复、ask 答复）> `later`（普通追问）。
   同级 FIFO；队列上限 20 条，超出拒绝并提示。
2. **打断决策表**：
   - 模型流式输出中收到 `later` 消息 → 当前 turn 正常收尾后立即消费（steer）；
   - 工具执行中收到消息 → 查该工具的 `interruptBehavior`：`cancel` 则真实取消
     （asyncio.Task 取消 + 推送 `tool.cancelled`），`block` 则排队等工具结束；
   - 任何时刻收到 `next` 类控制消息 → 立即处理，禁止排队。
3. **SSE 增量事件**：`message.queued`、`message.dequeued`、`run.interrupted`、`tool.cancelled`。
4. **取消真实性**：取消必须贯穿到工具执行层与（如已发出）模型流式请求的中断，
   禁止"前端显示已停止、后端仍在计费生成"。

**边界红线**：
| # | 红线 |
|---|------|
| 1 | 取消指令未真实传递到执行层（仅改 UI 状态）→ 否决 |
| 2 | 控制类消息（confirm_token/ask 答复）被普通排队阻塞导致超时 → 否决 |
| 3 | 工具未声明 `interruptBehavior` 默认按 `block` 处理，禁止隐式 cancel |
| 4 | 打断后的半截消息必须标记 `interrupted=true` 落库，禁止以完整消息呈现 |

### 2.4 AgentTodo 可见任务清单（P1）

**需求说明**：
1. 内置工具 `todo_write`：`items[] = {content, status: pending|in_progress|completed}`，
   仅允许在多阶段子 Agent 任务（组卷、学情分析、PPT 生成、DreamTask）中使用。
2. 每次更新推送 `card` 事件（`card_type: todo_list`），Flutter 渲染 checklist。
3. 约束：同一时间只允许 1 个 `in_progress`；全部 completed 前禁止产出最终交付卡片。
4. Todo 快照随 `agent_runs` 落库（JSONB），用于回放与审计。

**边界红线**：
| # | 红线 |
|---|------|
| 1 | Todo 仅作进度可视化与 Agent 自约束，**禁止充当业务数据存储**——学习计划任务走 `study_plans` 表，复习项走 `flashcards` 表 |
| 2 | 禁止多个 in_progress 并存；禁止跳状态（pending 直接 completed 需有对应工具执行记录佐证） |
| 3 | 前端 todo 卡片只读，禁止用户直接勾选修改（用户操作走 ask/plan 通道） |

### 2.5 Stop Hooks 收尾校验（P0）

**需求说明**：
1. **机制**：模型输出 stop 意图时，编排层按当前上下文匹配已注册校验器；校验失败则把
   失败原因作为 blocking 消息注入 Loop 强制继续，**同一 run 最多强制继续 2 次**；
   第 3 次仍失败 → 携带 `warning` 标记交付并落审计。
2. **首批注册校验器**：
   - `math_verify`：数值/方程类答案经 SymPy 沙箱复核（方程解回代、表达式等值性）；
   - `grading_consistency`：批改结论与被引用的标准答案/评分细则一致性检查；
   - `completeness_check`：教案（目标/重难点/过程/板书/作业/反思六模块齐全）、
     试卷（题量/分值合计/答案解析齐全）、PPT（标题页/目录/正文/总结页齐全）完整性校验。
3. **校验器要求**：确定性代码或推理网关小模型；单次执行 ≤2s；结果与理由落 `stop_hook_audits`。

**边界红线**：
| # | 红线 |
|---|------|
| 1 | 强制继续无上限（死循环烧 Token）→ 否决；上限固定 2 次 |
| 2 | 校验器单次 >2s 或引入新的外部网络依赖 → 否决 |
| 3 | 校验器只许读上下文与沙箱计算，**禁止写业务表**（写入由 Loop 正常路径完成） |
| 4 | 带 warning 交付的内容必须在前端有可见标识，禁止静默降级 |

## 三、分档二：上下文与成本工程

### 3.1 Prompt-Cache 感知压缩（P1）

**需求说明**：
1. **前缀稳定区**：System Prompt 主体、工具定义、记忆注入区块、Output Style 区块，
   位于消息序列前缀，要求**字节级稳定**——压缩管线只允许在"压缩边界之后"编辑，
   禁止重排/改写前缀任何字符。
2. **缓存破坏检测**：每次请求前计算前缀 hash 并与上一次对比；破坏即落审计并告警，
   附带定位到具体变更来源（哪一级压缩/哪次注入导致）。
3. **指标**：第三方 API 的缓存命中 token 占比纳入观测看板，目标 ≥ 60%（长会话）。
4. 与编排层四级压缩管线的关系：本机制是对其 L1–L4 的**约束增强**，不改变触发条件。

**边界红线**：
| # | 红线 |
|---|------|
| 1 | 任何压缩/注入逻辑改写前缀稳定区 → 否决 |
| 2 | 记忆注入位置禁止逐字变动（排序固定、截断规则固定、时间戳等易变字段禁止出现在前缀） |
| 3 | 缓存破坏只有日志没有告警 → 视为未实现 |

### 3.2 ToolUseSummary 工具摘要（P2）

**需求说明**：每个工具执行完成后生成 ≤50 字一句话摘要，双用途：
① UI 展示（"正在使用 作业批改…"的后续说明）；② 压缩管线的占位文本。
**生成策略**：优先模板拼接（工具名+关键参数+结果状态），模板不覆盖时经推理网关小模型生成。

**边界红线**：
| # | 红线 |
|---|------|
| 1 | 模板命中率 <80% 视为未达标；小模型路径单次 ≤100ms 且失败必须回退模板 |
| 2 | 摘要禁止包含用户隐私原文（如整段作文），只允许元信息级描述 |

### 3.3 Denial Tracking 拒绝追踪（P2）

**需求说明**：
1. `denial_counters` 表记录（user_id, target_code）维度的 `consecutive / total` 拒绝计数；
   target 可为 Skill、工具、追问推荐类别。
2. **阈值策略**：consecutive ≥3 → 该类别推荐降频（排序沉底）；total ≥20 → 默认关闭并下次启动时提示。
3. **恢复**：用户主动使用一次 → consecutive 清零。

**边界红线**：
| # | 红线 |
|---|------|
| 1 | 计数只影响推荐排序与默认值，**禁止用于限制用户主动发起的功能** |
| 2 | 拒绝数据不出域、不共享，禁止用于用户画像外的用途 |

### 3.4 Cost Tracker 成本台账（P1）

**需求说明**：
1. `cost_ledger` 表逐 run 记录：model_route、input/output/cache_hit tokens、
   单价快照、折算成本（美分）、身份档。
2. 实时聚合用户月度用量，与编排层配额/预算校验联动（护栏链第③环读取）。
3. 单价表存数据库按 provider+model 配置，支持历史快照（对账可溯源）。

**边界红线**：
| # | 红线 |
|---|------|
| 1 | 单价硬编码进代码 → 否决 |
| 2 | 前端只见配额百分比，禁止暴露成本明细与单价 |
| 3 | 台账写入失败必须降级为异步补写并告警，禁止因记账失败阻断用户请求 |

## 四、分档三：智能增值机制

### 4.1 PromptSuggestion 追问推荐（P2）

**需求说明**：
1. 每个 run 正常结束后，经推理网关小模型基于当前会话生成 3 条候选追问，
   以 SSE `suggestions` 事件推送，Flutter 渲染为输入框上方 chips。
2. **speculation 预取**（可选，默认关闭，Feature Gate 控制）：仅允许预取**只读数据**
   （相关题目、知识点条目），禁止预取任何生成类/计费类任务。
3. 推荐内容必须过内容审核（护栏链第①环复用）后方可下发。

**边界红线**：
| # | 红线 |
|---|------|
| 1 | 推荐未过内容审核即下发 → 否决 |
| 2 | 推荐生成禁止跨会话挖掘（只用当前会话 + 当前学科上下文） |
| 3 | speculation 默认开启或预取生成类任务 → 否决 |

### 4.2 DreamTask 夜间记忆整合（P1）

**需求说明**：
1. **触发**：Celery beat 每日低峰（默认 02:00–05:00 分批）；只处理当日有活动的用户。
2. **四阶段固定流水线**：`orient`（盘点当日会话与工具产物）→ `gather`（错题聚类、
   知识点归并）→ `consolidate`（更新知识点掌握度矩阵、生成/更新复习卡片、沉淀长期记忆）
   → `prune`（清理过期缓存与临时文件）。阶段产物落 `dream_runs`。
3. **并发锁**：Redis 分布式锁（用户粒度），锁冲突即跳过该用户当日整合，禁止并发双跑。
4. **产出呈现**：次日用户首次启动推送 `card_type: dream_summary` 卡片
   （"已为你整理昨日 3 道错题，生成 5 张复习卡"）。
5. 失败重试 ≤2 次，且禁止挤占白天服务资源（低优先级队列）。

**边界红线**：
| # | 红线 |
|---|------|
| 1 | 禁止修改用户原始消息与原始错题内容（只新增/更新派生数据） |
| 2 | 推送内容必须经内容审核；自动生成的复习卡需标"AI 生成" |
| 3 | 未持锁执行整合 → 否决；整合任务出现在同步请求路径 → 否决 |

### 4.3 工具延迟加载与搜索发现（P1）

**需求说明**：
1. **常驻工具集 ≤4 个**（按角色配置，如学生：ocr_extract/calculator/ask_user_question/sub_agent_dispatch），
   其余工具标记 `deferred=true`，不进初始 System Prompt。
2. 内置 `tool_search` 工具：按 name+description 关键词检索 deferred 工具，
   命中后**当轮动态挂载**其 Schema，下轮自动卸载。
3. 搜索索引构建时按角色过滤——该身份不可见的工具（如学生搜教师工具）不进索引。

**边界红线**：
| # | 红线 |
|---|------|
| 1 | 角色不可见工具出现在搜索结果 → 否决（越权等价于护栏失效） |
| 2 | 动态挂载仅当轮有效，禁止常驻化规避上下文控制 |
| 3 | 常驻工具集 >4 需架构评审批准（上下文成本敏感性） |

## 五、分档四：工程基础设施

### 5.1 分段 Checkpoint 观测（P1）

**需求说明**：Agent Loop 各阶段打点计时，阶段枚举固定：
`slim / compact / memory_prefetch / model_first_token / guardrail / tool_exec / docgen_wait / total`。
每 run 的 timings JSONB 落 `agent_runs`；p95 超阈值告警（阈值配置化）。

**边界红线**：
| # | 红线 |
|---|------|
| 1 | 埋点数据只含计时与计数，禁止携带消息内容/用户输入原文 |
| 2 | 埋点开销 >5ms/run 视为缺陷 |

### 5.2 Feature Gates 灰度（P2）

**需求说明**：`feature_gates` 表（key / enabled / rollout_pct / allowlist），进程内缓存 60s；
判定入参含 user_id 哈希分桶。新机制（speculation、新身份功能、新学科模型）默认 gate=off。

**边界红线**：
| # | 红线 |
|---|------|
| 1 | 禁止用 `if env` 散落硬编码代替注册表 |
| 2 | Gate 判定禁止绕过 RLS 与护栏链（gate 只管功能可见性，不管权限） |

### 5.3 Output Styles 风格注册表（P2）

**需求说明**：`output_styles` 表（grade_level + subject → tone_prompt），
注入 System Prompt 固定区块 `<output_style>`；支持运营后台增改，热生效。

**边界红线**：
| # | 红线 |
|---|------|
| 1 | 风格只影响表述方式，禁止影响事实正确性与内容审核标准 |
| 2 | 风格模板禁止包含绕开护栏的指令（上线前需安全评审） |

### 5.4 自动化 Hooks 与降级路径（P1）

**需求说明**：
1. **自动化 Hooks**：`automation_hooks` 表配置 `event → action`，首批事件
   `mistake.created / plan.confirmed / dream.completed`，首批动作
   `notify_parent / notify_teacher`；全部异步执行（Celery），失败不影响主流程。
2. **降级路径声明**：每个多模态功能必须在配置中声明降级链——
   语音对练 → 文本对练；拍照搜题 → 相册上传 → 手动输入题干；OCR 批改 → 手动框选。
   服务故障时自动切换并**明示用户**（"语音服务暂不可用，已切换文本模式"）。

**边界红线**：
| # | 红线 |
|---|------|
| 1 | Hook 动作出现在同步请求路径 → 否决 |
| 2 | 降级切换未明示用户 → 否决（禁止静默降级体验） |
| 3 | 新增多模态功能未声明降级链 → 不予上线 |

## 八、非功能性指标（本扩展包，硬性）

1. ask/plan 挂起与恢复 p95 < 500ms（不含用户等待时长）；
2. Stop Hook 单校验器 ≤2s，整链 ≤4s；
3. 工具摘要模板命中率 ≥80%；
4. 长会话第三方 API 缓存命中 token 占比 ≥60%；
5. DreamTask 单用户整合 ≤60s，全量批次在 3 小时窗口内完成；
6. 追问推荐生成 ≤800ms，失败静默降级为不推荐（不影响主响应）；
7. 埋点开销 <5ms/run。
